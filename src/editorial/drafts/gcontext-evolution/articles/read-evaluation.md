The illustrative guide now points to Reports. A later session can read the corrected instruction instead of repeating the earlier search.

That is the intended outcome. It still needs evaluation. The agent might load unrelated material, find the answer elsewhere, or discover that the guide has become outdated again.

## Compare the same task with different context

A BJJGym trial tested five questions with four ways to load saved knowledge. These were real project questions, separate from the export example used to explain this journey.

| Mode | What the agent received |
| --- | --- |
| No handbook | The question |
| Map | The handbook index and usage instructions |
| Facts | Selected facts and usage instructions |
| Map and facts | Both forms of context |

The trial recorded twenty runs, one for each question and mode.

For questions already answered in the repository, the agent could find the information without a handbook. Reading the map could add work before the agent checked the same source files.

For one question, the handbook offered a shorter route. The run without it accessed a live service and obtained fresher detail. Those were different behaviors, which limits a simple speed comparison.

## Current knowledge matters as much as access

The trial exposed a stale handbook fact. The initial answer key contained the same error and needed correction.

Some runs also accessed live systems beyond the isolated checkout. All answers passed the model's grading in the saved report, but the key had no independent validation. There was only one run per case.

These limits prevent a general claim that the handbook improved performance.

The useful question is whether saved knowledge helps the next task find a relevant, current answer. That connects the whole effort: access, selection, updates, and review all serve later use.
