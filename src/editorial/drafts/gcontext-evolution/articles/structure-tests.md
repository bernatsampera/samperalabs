## Replay real material and inspect each stage

The framework work added redacted replay cases from diversity-map and saved evidence from processing stages.

The saved evidence made the process inspectable: which input produced a note, where it went, and what existing text changed.

The method needed to reflect different purposes across projects without depending on one project's vocabulary.

## Separate meaning from tree construction

The property-tree experiment tried one division of work. A model proposed semantic properties. Code compared orders of those properties to construct trees.

For five properties, there are 120 possible orders. Code can compare that defined set. It cannot prove that the model chose the best properties in the first place.

This made one part of the problem explicit while leaving another open.

## A good starting tree still needs good updates

Classifying information once does not explain how to maintain it. Later facts may replace an old rule, affect several files, or make a document redundant.

Those failures made the update itself important to inspect. Placement alone did not explain how the system found and changed related passages.
