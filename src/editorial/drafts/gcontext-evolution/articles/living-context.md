A task can produce a useful correction alongside guesses, failed attempts, and details that matter only for that run.

Preserving the whole conversation would make later sessions inspect that history again. Keeping a short finding is more focused, but a new note can introduce another problem.

## Two files can disagree

In the illustrative export example, the guide still says to open Settings. A new note says to open Reports.

The correction has survived, but the next agent can now encounter both versions.

| Saved material | Instruction |
| --- | --- |
| Existing guide | Open Settings |
| New finding | Open Reports |

This is a simplified example of conflicting guidance, not a recorded test result.

The aim is to preserve useful knowledge in a form that later tasks can use. That can require changing an existing passage rather than adding another note.

## Different records need different rules

The early platform separated integration instructions, task records, and reusable workflows. They served different purposes and needed different kinds of maintenance.

A task record can retain the history of an investigation. A reusable procedure should explain what a later run needs to do. Copying every temporary detail into that procedure can make it harder to follow.

Later folder-rule experiments made the purpose more explicit: what belongs here, what should be ignored, and when should existing text change?

Real conversation records exposed repeated information and fragmented notes. Saving more material did not necessarily create better context.

The next problem was therefore precise: find the information affected by a correction and update it without losing useful detail.
