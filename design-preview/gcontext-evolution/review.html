Building shared context
for AI agents

I am building gcontext to give AI agents access to useful knowledge and a way to keep that knowledge current. The work started with project files and service integrations. It now includes rules for saving information, reviewing changes, and testing whether the saved context helps with real work.

Giving agents access to knowledge and services

A personal agent became a workspace with context that could be selected for each task.

I built a personal agent that could find information across my repositories and use service APIs. Bleak added a workspace where I could see the knowledge, select context, and work with the agent.

Reviewing changes and testing their value

The next step was to test updates, inspect their effects, and check whether the saved knowledge helped another session.

Comparing methods for updating a handbook

I compared direct file editing, whole-handbook input, and methods that select relevant facts. The recorded review found a useful tradeoff: smaller inputs could find related facts, but some edits damaged the original text.

Read the article direction +

An update can affect several files

The saved evaluation used cases where a changed rule appeared in different forms across a handbook. A direct search could miss a paraphrase. Sending the whole handbook gave the model more evidence, but required much more input. The tests compared these approaches with methods that selected facts first.

Passing checks did not guarantee a good edit

The October evaluation reported that methods based on a fact index could overwrite original lines with paraphrases. One table row became a sentence inside the table. Some instructions lost useful wording. The automated checks passed because they tested the fact change more narrowly than the quality of the document.

The diff mattered as much as the score

This is a strong article about how to evaluate an AI update system. It can compare the source line, the proposed operation, and the resulting file. The saved report also identifies a disputed test case and limited repeats. It supports a discussion of tradeoffs, not a claim that one method won in general.

Material for the article

Testing whether saved context helps an agent answer

I tested five BJJGym questions with four ways to load context. The saved results showed where a handbook could help and where it added work. They also exposed a stale fact and limits in the test setup.

Read the article direction +

Saving information is only useful if it helps later work

The November trial compared no handbook, a navigation map, selected facts, and both the map and facts. Each mode received the same five questions. The saved log records twenty runs, with one run per question and mode.

The results depended on where the answer lived

For questions already answered in the repository, the agent could find the information without the handbook. The map sometimes added reading cost. For one question, the handbook gave a shorter path to an answer. The run without it used a live service and obtained fresher detail. Those are different behaviors, not a clean speed comparison.

The trial also tested the evaluation itself

The agent checked the repository and found that a handbook fact was outdated. The original answer key had the same error. Some runs also left the isolated checkout to read live systems. The article should explain these limits and the lack of repeated runs. All answers passed the model's grading, but the author had not validated that key in the saved record.
